1. THE THREE-CATEGORY CHECKPOINT RULE (read carefully -- do NOT conflate)
--------------------------------------------------------------------------------
There are THREE fresh-start frame categories, governed by DIFFERENT rules. P.11C
must treat them distinctly:

(1) DETECTED-CUT frame K (first frame of a NEW scene):
    - reached via a NORMAL RECURSIVE compute -- it HAS a predecessor (output[K-1]);
    - the detector runs (current source K vs previous filtered K-1), returns "cut";
    - output[K] computed as fresh-start (chroma-copy, chain severed) AND STORED WITH
      THE CHECKPOINT FLAG SET. CMS 6.4 / 9.2. *** P.11C WIRES THIS -- it is the core
      of the phase. A scene change MAKES THE NEW FRAME A CHECKPOINT, via detection. ***

(2) FRAME 0:
    - no predecessor exists -> detection CANNOT run (nothing to diff);
    - fresh-start for STRUCTURAL reasons;
    - IS a checkpoint, but by the §6.3 GRID rule (frame 0 always grid checkpoint),
      NOT by detection. P.11C does not touch this.

(3) BOUNDED-SEARCH FLOOR (max(0,N-B)):
    - no in-window predecessor -> detection CANNOT run;
    - fresh-start for STRUCTURAL reasons;
    - checkpoint only if it lands on the §6.3 grid; not made a checkpoint by detection.

DETECTION-NOT-APPLICABLE applies to categories (2) and (3) ONLY -- the structural
fresh-starts with no predecessor to detect against. It does NOT touch category (1).
P.11C wires detection ONLY at live recursive computes that HAVE a valid previous
filtered output: branch-c target, branch-d hole computes, branch-d target.
(No CMS change -- this is CMS-consistent per §1/§6.3/§6.4; recorded as a scope boundary.)

2. SCOPE ITEMS (what to build)
--------------------------------------------------------------------------------

S1. LIVE SCENE-CHANGE CONFIG (per-instance).
    - Add/populate Cnr3SceneChangeConfig {scene_change_threshold:int64, scene_chroma:bool}
      in INSTANCE/FILTER DATA (not a compile-time flag), so later plugin parameters can
      feed it without rewiring the live path.
    - P.11C live defaults: scene_chroma = false (luma-only; safer first default for a
      chroma denoiser on noisy analogue chroma). Threshold = a NAMED CMS/proof default;
      proposed dimension-scaled luma-only value:
          threshold = chroma_width * chroma_height * 4 * 20
      (~avg luma diff 20 over the chroma grid; 4 == 1 << (sub_sampling_w + sub_sampling_h)).
      Designer to ratify the exact named default before commit; for PROOF harnesses use
      constructed clips + explicit thresholds that force cut/no-cut deterministically.

S2. ENABLE DETECTION AT THE LIVE RECURSIVE COMPUTE SITES.
    - Use cnr3_process_caller_supplied_vapoursynth_frame_triplet_with_scene_change
      (passing the Cnr3SceneChangeConfig) at the sites that HAVE a valid previous
      filtered output:
          branch-c: predecessor-present TARGET compute;
          branch-d: recovery HOLE compute;
          branch-d: recovery TARGET compute.
    - Do NOT force the scene-change variant into fresh-start/floor (category 2/3): they
      have no predecessor. Keep the two public entry points distinct (do not collapse).
    - Reset is FREE: once the scene-change variant runs, the existing reset (chroma-copy
      on cut) is exercised live. No new pixel reset algorithm. P.11C PROVES it runs live.

S3. THREAD scene_change_detected INTO EVERY COMPUTED-OUTPUT STORE THAT CAN PRODUCE A CUT.
    (This is the coder's key correction -- it is BROADER than the final-target wrapper.)
    Sites:
          branch-c final TARGET store;
          branch-d per-HOLE stores;
          branch-d final TARGET store.
    Decision (centralised, not scattered):
          store_as_checkpoint = grid_checkpoint || scene_change_detected
    via ONE helper, e.g. cnr3_live_output_frame_should_store_as_checkpoint(...), so the
    "grid || scene" logic is not duplicated across branches.
    Threading shape: prefer a small store-request struct or named boolean over another
    anonymous bool param, e.g.
          struct Cnr3LiveOutputStoreRequest { int frame_number; bool force_checkpoint; };
    Designer to ratify the public shape.

S4. CHECKPOINT STORE/PROMOTION -- ATOMIC, PROMOTE-ONLY (CMS 6.6).
    - The checkpoint flag/promotion decision MUST enter the AS2 store atomic. It must
      NOT be a later separate promotion under a second lock.
    - Primitive by site:
          isolated final-target store (no pin)  -> store_checkpoint_owned_frame(...)
            (its promote path raises an existing non-checkpoint slot to checkpoint);
          recovery stores that ALSO pin         -> the combined store-and-pin path with
            is_checkpoint, e.g. store_owned_frame_and_record_pin(..., is_checkpoint, ...)
            or the planned-hole variant store_recovery_plan_hole_owned_frame_and_record_pin
            (..., is_checkpoint, ...). Flag-set AND pin-record under the SAME atomic.
    - The exact primitive name is not the requirement; the ATOMIC + PROMOTE-ONLY property
      is. Confirm the exact call shapes against the latest source (item 0).

S5. PER-HOLE CHECKPOINTING IN RECOVERY (branch-d).
    - CMS 9.2: if a cut is detected at hole K, output[K] is reset/fresh-started, stored
      WITH the checkpoint flag, and the ascending walk continues. So each hole's store
      must take that hole's own scene_change_detected bit and checkpoint/promote that hole
      atomically -- NOT only the final target.
    - Detection against a reconstructed predecessor (floor output or prior hole output) is
      CORRECT: the reconstructed predecessor IS the previous filtered output for the
      ascending walk; it need not be cache-resident before compute.

S6. KDT PROOF FIELDS.
    Per-frame (live): p11c_called, scene_change_deferred, scene_change_detection_used,
      scene_chroma_used, scene_change_threshold, scene_change_diff_total,
      scene_change_samples_examined, scene_change_detected, scene_change_reset_output_used,
      recursive_chroma_blend_used, store_as_checkpoint, scene_checkpoint_store,
      checkpoint_promoted, resulting_slot_is_checkpoint.
    Per-hole (recovery): hole=K, hole_scene_change_detected, hole_scene_change_reset_output_used,
      hole_store_as_checkpoint, hole_resulting_slot_is_checkpoint (or equivalent compact lines).
    On enabled branches, flip p11c_called=1, scene_change_deferred=0, scene_change_detection_used=1.

3. PROOF (synthetic; live harness primary; NO new cache-core selftest needed)
--------------------------------------------------------------------------------
G.12A COVERAGE CONFIRMED (designer checked source): the existing selftest
cnr3_cache_core_selftest_checkpoint_store_flag_lifecycle ALREADY proves the §6.6
monotonic-checkpoint primitive at cache-core level (store non-checkpoint -> store
checkpoint duplicate returns `duplicate`, raises checkpoint_count 0->1 = PROMOTION,
preserves frame identity; plus the never-demote direction). Therefore P.11C does NOT
add a cache-core selftest for the promotion primitive -- it would duplicate G.12A.

P.11C proves the LIVE WIRING via a synthetic live harness (constructed cuts), asserting:
    detection used; cut detected; reset output used; recursive blend NOT used;
    output chroma == current source chroma; output stored/promoted as checkpoint;
    a later recovery finds that detected-cut frame as an anchor.
Branch coverage (may be split into proof subphases -- designer decides subphasing):
    - branch-c no-cut control;
    - branch-c cut at target N;
    - branch-d cut at intermediate hole K;
    - branch-d cut at final target N;
    - later recovery using a detected-cut frame as anchor.
Robust-proof note: at tuned thresholds the recursive output moves ~1 LSB frame-to-frame,
so prove via the KDT mechanism + direct byte checks (output chroma == current source on a
cut), NOT a byte margin. Designer supplies the verified golden values.

Selftest ONLY if the live harness cannot deterministically force the live promote path
through the EXACT combined store-and-pin helper -- and even then only a narrow proof not
already covered by G.12A. Default expectation: live harness suffices.

4. fmParallel INTERLEAVING (carry in the design note; no stress validation in P.11C)
--------------------------------------------------------------------------------
    - checkpoint flag raise-only, never demote;
    - duplicate checkpoint store promotes an existing non-checkpoint slot (data unchanged);
    - duplicate non-checkpoint store cannot demote an existing checkpoint;
    - pin count and checkpoint flag coexist under cache lock;
    - recovery store-and-pin and checkpoint promotion under ONE atomic;
    - no after-the-fact second-lock promotion.
Benign interleavings to cite: (A stores K non-cp; B detects K cut -> promotes),
(A stores K cp; B computes K non-cp -> no demote), (A pins/adopts K while B promotes K
-> pin+flag coexist under the cache lock). Actual fmParallel STRESS validation is deferred.
