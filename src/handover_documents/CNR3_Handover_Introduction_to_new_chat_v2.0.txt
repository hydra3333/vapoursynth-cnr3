The next coding direction is now not the old one-step H15.6B source-request reduction.
Instead, follow CMS06.11 and implement the revised H15.6B in three proof subphases:

1. `CMS02-H15.6B.1 / arInitial predecessor reservation lifecycle proof`

   Add `frameData` ownership for a reserved predecessor ref acquired in `arInitial`
   via atomic `find_frame_and_add_ref(N-1)`.

   Carry it across `arInitial -> arAllFramesReady`.

   Do not reduce source requests yet.

   Prove:

   * acquisition;
   * carry;
   * cleanup;
   * named/null-guarded release-helper behaviour;
   * lookup-ref balance;
   * no checkpoint pin misuse;
   * no non-checkpoint pin misuse;
   * ordinary cached predecessor reservation uses lookup-addref ownership, not pinning.

2. `CMS02-H15.6B.2 / reserved-predecessor fast-path consumption proof`

   Use the carried reserved predecessor ref as the fast-path predecessor instead of re-looking up `N-1` in `arAllFramesReady`.

   Keep conservative source requests.

   Prove the single-ownership/null-on-consume rule:

   * the reserved predecessor ref is owned by `frameData` until consumed;
   * successful fast-path consumption releases or consumes the ref and sets the `frameData` field to null;
   * `frameData` cleanup releases the ref only if the field is still non-null;
   * consumed refs must not also be released by cleanup;
   * unconsumed/error-path refs must be released by cleanup;
   * no double-release and no leak.

   Required proof evidence should include the CMS06.11 strengthened fields, including field-null-after-consume and field-null-after-cleanup style evidence.

3. `CMS02-H15.6B.3 / active sequential source-request reduction`

   Only after B.1 and B.2 pass, reduce safe class-B sequential fast-path candidates to request source `N` only.

   H15.6B.3 source-request reduction is eligible only if `arInitial` successfully acquired and stored a reserved predecessor ref for `output_cache[N-1]`.
   A cache-contains check or other non-owning observation that `N-1` exists is not sufficient.

   Keep frame-zero, predecessor-missing, non-sequential, uncertain, and fallback cases on conservative bounded-warmup source requests.

Important standing rule from this point onward:

Every cache-affecting proof or validation phase must explicitly prove both ownership systems where relevant:

* Lookup-addref ownership for ordinary cached-frame use, including acquired/released/transferred counts and zero lookup-ref balance.
  Reserved predecessor refs are part of this same lookup-owned-ref accounting universe.
  They are not a separate ownership system.
  For H15.6B.1 and H15.6B.2, the reserved predecessor is an input, not the returned frame, so it is released, not transferred.

* Checkpoint pin/unpin ownership for checkpoint/recovery anchors, including pin/unpin counts,
  underflow/failure checks, `total_pin_count=0`, and `has_pinned_checkpoints=0` at cleanup.

Also preserve the future H17 optimization note:

The current fallback is correctness-first and conservative.
It may retrieve/recompute a bounded lower frame even when that output is already cached,
relying on first-in-best-dressed duplicate handling to discard duplicate output safely.

A later H17-style sparse-hole/minimal recovery path should start from the nearest suitable
cached predecessor/checkpoint inside the bounded recovery window, retrieve only the missing
source frames needed to walk forward, compute/store only missing outputs plus the requested
output, and return through output-cache authority.

This H17 work is deferred. It must not contaminate H15.6B.1, H15.6B.2, or H15.6B.3.

Please do not claim fmParallelRequests or fmParallel readiness until each is fully tested as ready.

The design is still moving toward fmParallelRequests then fmParallel,
but CMS02-J0 cleanup/observability review and later fmParallelRequests/fmParallel
work remain outstanding.

Old strict state remains quarantined but not yet retired.
