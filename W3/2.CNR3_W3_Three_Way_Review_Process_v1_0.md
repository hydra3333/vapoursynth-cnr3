# CNR3 W.3 — Three-Way Review Process and Rules (v1.0, adapted from Step 0 Joint Review PROCESS v1.1)

**Purpose.** W.3 is the highest-consequence phase of the live cache-pressure wiring arc — the §7.5 combined
live store-and-prune helper, where the cache first EVICTS frames. This document defines HOW the four of us run
a pre-code design + scope review of it, BEFORE any wiring patch, modelled directly on the Step 0 joint review
that worked (`x_CNR3_Step0_Joint_Review_PROCESS_v1_1.md` — read it if you want the parent rules; this is its
W.3 instance). The review itself lives in a single append-only register file (the Round-0 seed accompanies
this). A CMS clarification or a scope change MAY be an output of this review — that is legitimate, not a
precondition skipped.

## 0. Roles — KNOW YOUR LABEL

- **W3D — Designer** (me; holds W.3 design intent + the CMS/architecture lens; seeds the register Round 0).
- **W3C — Coder** (holds implementation feasibility; the live-path / lifecycle / atomicity lens).
- **W3OD — Old Designer** (independent D-side cross-check; holds the prior-design lineage and Step-0 memory;
  a second reviewing voice on the design side for this high-consequence phase).
- **W3X — Coordinator** (Dave; final authority; relays the register file between reviewers; keeps the
  authoritative copy and the next-free comment number; rules ties).

W3D, W3C, and W3OD are the three REVIEWING parties. W3X is authority and relay; W3X need not raise findings
but rules disputes and waives blockers. Each reviewer: you are reviewing the W.3 SCOPE + design (and later the
PATCH), not writing production code in this phase.

## 1. Single-register principle (no merge step)

There is ONE register file. Every finding and every comment is appended to it; nothing is edited away or
silently dropped. The register is always the single source of truth; W3X holds the authoritative copy and
relays it. Do not fork it, do not summarise-and-replace it — APPEND.

Rounds (the file changes hands via W3X; round number increments each hand-off):
1. **Round 0 (seed):** W3D populates the register with the W.3 scope + opening designer findings + the
   non-exhaustive issue list. (This is the accompanying seed.)
2. **Round 1:** W3X relays to W3C and W3OD. Each appends their findings (`SR-C-*` / `SR-OD-*`) and comments on
   W3D's findings. Returns to W3X.
3. **Round 2:** W3X relays back to W3D. W3D comments on the new findings, raises any new `SR-D-*`, updates
   statuses. Iterate until all BLOCKER/MAJOR findings are AGREED / RESOLVED / DEFERRED.

## 2. Finding IDs (stable, owner-tagged, never reused)

`SR-<OWNER>-<NN>` where `<OWNER>` = `D` (W3D) / `C` (W3C) / `OD` (W3OD) / `X` (W3X) — the party who FIRST
raised it; owner never changes. `<NN>` = zero-padded per-owner sequence, increasing, never reused
(`SR-D-01`, `SR-C-01`, `SR-OD-01`, …). A finding is never deleted — its status becomes `WITHDRAWN` (by its
owner) or `REJECTED` (by W3X ruling). A concern one party's comment spawns is raised as that party's OWN new
finding and cross-linked, never re-owned.

## 3. Finding anatomy

```
### SR-D-03   [severity: MAJOR]   [status: OPEN]
Finding (W3D): <one clear statement of the concern, gap, or question>
<comments appended below, newest last>
```
- **severity:** `BLOCKER` (must be resolved or explicitly W3X-waived before ANY wiring code) / `MAJOR` (must
  reach AGREED/RESOLVED/DEFERRED before wiring code) / `MINOR` (note; need not block).
- **status:** `OPEN` / `ACKNOWLEDGED` / `AGREED` / `DISAGREED` / `PARTIAL` / `DEFERRED-to-<arc>` / `RESOLVED`
  / `WITHDRAWN` / `REJECTED`.

## 4. Comment anatomy (the heart of the protocol)

```
[#<SEQ> | <AUTHOR> | r<ROUND> | <verdict>]  <reasoning — REQUIRED, always>
```
- `<SEQ>` = global next-free integer (W3X keeps it; not datetime).
- `<AUTHOR>` = `D` / `C` / `OD` / `X`. No anonymous comments.
- `<verdict>` = `ack` / `agree` / `disagree` / `partial` / `withdraw` (owner) / `ruling` (W3X only).
- **Reasoning is REQUIRED for EVERY verdict, including `agree`** — a bare "agree" is lossy and hides whether
  you agree for the SAME reason. **The honest-agree rule:** if your `agree` only holds for a NARROWER claim
  than the finding states, say so explicitly and mark it `partial`, not `agree`. (This rule caught real gaps
  in Step 0 — e.g. the frame-0 double-guard and the recovery-token mismatch in W.2.)

## 5. Status transitions (the only legal moves)

`OPEN → ACKNOWLEDGED` (an `ack`); `ACKNOWLEDGED → AGREED` (BOTH/ALL relevant reviewers' LATEST verdicts are
`agree` with reasoning); `→ DISAGREED` (opposed verdicts standing); `→ DEFERRED-to-<arc>` (real concern, later
arc — must NAME the arc, e.g. `DEFERRED-to-fmParallel`); `→ RESOLVED` (question answered AND latest verdicts
align, or W3X ruled — the final comment records the agreed decision); `→ WITHDRAWN` (owner); `→ REJECTED`
(W3X ruling). **Hard rules:** a finding CANNOT reach RESOLVED on one party's say-so — verdicts align or W3X
rules; `disagree` keeps it open until reconciled or W3X rules; BLOCKER must be RESOLVED or explicitly
W3X-waived before any code.

## 6. Verify-against-source, don't defer

This review's findings are about LIVE BEHAVIOUR (eviction). Where a claim can be checked against the committed
W.2 source (the attached `src.zip`: `cnr3_arAllFramesReady.cpp`, `cnr3_cache_core.cpp/.h`, the CMS §7.4/§7.5/
§7.6), check it THERE and cite line/contract — do not assert from memory or from the scope's description.
Anything not sourceable from the tree is marked "confirm from repo". (This is the discipline that made the W.2
diff/harness reviews come out identical across reviewers.)

## 7. Hand-off summary (REQUIRED at the top of every relay)

Every time the register changes hands via W3X, the sending party leads with a short blurb: what changed this
round, which findings moved status, and what the receiving party most needs to look at. Leads with the
decision-relevant items, not a full re-read.

## 8. Exit

The review is DONE when every BLOCKER and MAJOR finding is AGREED / RESOLVED / DEFERRED-to-<named-arc>, and
W3D can write the W.3 coder build scope (and the designer-owned A/B + eviction-proof harness) from a closed
register — exactly as Step 0 closed into the W.1/W.2 scopes. Any CMS §7.5 clarification that falls out is a
legitimate output, recorded and relayed.
