Verdict:

D verdict: PATH-B-ONLY for the hot production path; skip D in this arc.

The source confirms production now calls the native C1 downsample path twice, for current and previous luma, rather than the scalar cnr3_downsample_luma_plane_to_chroma_grid path. The scalar function still exists as a tested primitive, but optimising it would be a production non-win.

For the hot native path, /Qvec-report:2 still reports the relevant native downsample loops as not vectorised, mostly reason 506, with only a separate simple loop vectorised. The native function preserves the exact asymmetric tap geometry and edge clamps, including x1 = x0 + 1 when available and the degenerate 4:4:4/4:4:0 horizontal-neighbour rule.

A value-exact interior/edge split is theoretically possible, but making it likely to auto-vectorise would require enough specialisation by storage width, subsampling, and edge shape that it becomes Path B-style kernel work, not a small safe D cleanup. At a ~1.3k leaf after the ~79% cumulative reduction, that does not clear the value/safety bar.

So E can proceed to build/test; D should be closed as “skip unless future explicit SIMD work is deliberately opened.”
